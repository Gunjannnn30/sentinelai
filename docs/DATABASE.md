# Database

Engine: **SQLite** for local dev (`SENTINEL_DATABASE_URL=sqlite:///./data/sentinelai.db`)
and **PostgreSQL 16+** in docker-compose/production
(`postgresql+psycopg://user:pass@host:5432/db`). The live deployment uses
**Neon's free-tier Postgres** — its connection string is a bare `postgres://`
URL, which `app/core/config.py` rewrites onto the psycopg v3 driver we ship.
Access via SQLAlchemy 2
(sync) sessions; timestamps are UTC. All tenant-scoped tables carry
`org_id VARCHAR(36)` — UUID strings generated by the application.

Schema is created by:

- **dev/test**: `Base.metadata.create_all` at startup (lifespan, non-production).
- **production**: **Alembic only** — `alembic upgrade head`
  (`scripts/migrate.sh`). CI runs `alembic check` against an empty database to
  detect drift between models and migrations.
- Current head: `98827150dfb3` — *"initial schema"* (revision chain starts there).

## Tables

### Identity & tenancy
| Table | Purpose / notable columns |
|---|---|
| `users` | `email (unique)`, `password_hash` (scrypt), `full_name`, `is_active` |
| `organizations` | `name`, `slug (unique)`, `retention_days`, `rate_limit_per_minute`, `budget_monthly_usd` |
| `memberships` | `org_id` + `user_id` + `role` (viewer/developer/admin/owner) — the tenancy edge every query joins |
| `teams` | per-org teams (`org_id`, `name`) |
| `team_members` | `team_id` + `user_id` |
| `projects` | per-org projects (`slug`, `is_default`) — chat requests can be attributed to one |

### Gateway configuration
| Table | Purpose / notable columns |
|---|---|
| `providers` | `org_id`, `kind` (mock/openai/anthropic/gemini/ollama), `base_url`, **`secret_ref` (name only — never a key)**, `enabled` |
| `model_configs` | `org_id`, `provider_id`, `model_key`, `display_name`, `capabilities` (JSON list), `context_window`, `input/output_cost_per_1m`, `pricing_source`, `priority`, `latency_class`, `enabled`, **`is_demo_data`** |
| `policies` | `org_id`, optional `project_id`, `name`, `enabled`, `severity`, `action` (allow/warn/mask/block), `scope` + `scope_role`, `conditions` (JSON), `version` |
| `policy_versions` | immutable snapshots: `policy_id`, `version`, `snapshot` (JSON), `changed_by` |

### Runtime records
| Table | Purpose / notable columns |
|---|---|
| `request_records` | one row per gateway call: `status`, `policy_outcome`, `provider_kind`, `model_key`, `route_explanation`, `latency_ms`, token/cost fields (`cost_pricing_source`, `estimated_cost_usd`), `error_category`, `blocked_reason`, char counts, **`prompt_content`/`response_content` — stored only when `SENTINEL_STORE_PROMPT_CONTENT=true`, and masked**, `is_demo_data` |
| `security_events` | guardrail findings: `category`, `severity`, `action_taken`, `rule_name`, `detail`, `masked_types` (JSON), linked `request_id` |
| `usage_metrics` | **daily rollup** keyed `org_id + day + model_key + provider_kind`: `requests`, `blocked`, `errors`, `total_tokens`, `cost_usd_sum`, `cost_known_requests`, `latency_ms_sum`, `latency_count` — powers analytics endpoints without scanning `request_records` |
| `audit_logs` | hash-chained audit: `org_id`, **`seq` (per-org monotonic)**, **`prev_hash`**, **`hash`**, `event_type`, `actor_user_id`, `actor_email`, `resource_type`, `resource_id`, `request_id`, `outcome`, `detail` (JSON) |

### Evaluations
| Table | Purpose / notable columns |
|---|---|
| `evaluation_datasets` | `org_id`, `name`, `description`, **`is_synthetic`** (labels demo cases) |
| `evaluation_cases` | `dataset_id`, `prompt`, `expected`, `reference`, `tags` (JSON) |
| `evaluation_runs` | `org_id`, `dataset_id`, `name`, `model_keys` (JSON), `status`, `baseline_run_id`, `started/finished_at`, `summary` (JSON) |
| `evaluation_results` | `run_id` + `case_id`, `model_key`, `status`, `output`, `error_category`, `latency_ms`, `total_tokens`, `estimated_cost_usd`, `metrics` (JSON) |

### Meta
| Table | Purpose |
|---|---|
| `alembic_version` | single-row migration cursor |

## Relations (tenancy-first)

```
users ──< memberships >── organizations ──< policies / providers / projects / teams
                                     ├──< request_records ──< security_events
                                     ├──< usage_metrics (daily rollup)
                                     ├──< audit_logs (hash-chained seq)
                                     └──< evaluation_datasets ──< evaluation_cases
                                                              └─ evaluation_runs ──< evaluation_results
```

## Conventions & invariants

1. **Org scoping in code, not in constraints**: every SELECT/WHERE includes
   `org_id` resolved from the session (see `app/services/deps.py`). Postgres
   RLS is *not* configured — see residual risks in SECURITY.md.
2. **JSON columns** (`conditions`, `capabilities`, `summary`, `metrics`,
   `masked_types`) are `JSON` type — SQLite and Postgres both store them as
   TEXT/JSONB transparently through SQLAlchemy.
3. **IDs** are UUID4 hex strings (`VARCHAR(36)`), generated app-side so keys
   never leak counts/ordering.
4. **Audit chain**: `hash = H(seq | prev_hash | canonical(event))`;
   `verify_chain()` recomputes and reports the first mismatching `seq`.
   Seeding/writes must preserve `seq = max(seq)+1` per org.
5. **Retention**: `request_records` cleanup honors
   `organizations.retention_days` (`SENTINEL_DEFAULT_RETENTION_DAYS` default);
   audit events follow `SENTINEL_AUDIT_RETENTION_DAYS` (365).
6. **Demo data**: rows created by the first-boot seeder are flagged
   `is_demo_data`/`is_synthetic` so the UI can label them and admins can find
   them.

## Migrations

```bash
./scripts/migrate.sh                 # upgrade head
./scripts/migrate.sh current         # show revision
./scripts/migrate.sh downgrade -1    # rollback one step
# or directly, from backend/:
../.venv/Scripts/python -m alembic revision --autogenerate -m "describe change"
```

- Autogenerate against a **dev** database (its schema comes from models), then
  review the produced file before committing.
- CI applies migrations to a scratch DB and runs `alembic check` to catch
  model/migration drift.
- Never edit an applied revision; add a new one.

## Backups

- SQLite: copy `backend/data/sentinelai.db` while the app is stopped (or use
  `sqlite3 .backup`).
- Postgres: `pg_dump -Fc sentinel > backup.dump` on a schedule; restore with
  `pg_restore`. Compose persists data in the `pgdata` volume.
- Audit export (`GET /api/v1/admin/audit/export`) is the external anchor for
  tamper detection — archive it with backups.
